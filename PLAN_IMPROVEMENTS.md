# План улучшения проекта KP Generator

План сформирован в порядке убывания важности и охватывает архитектуру, безопасность, пользовательский опыт, данные, администрирование, интеграции и процессы разработки.

## 1. Надёжность, безопасность и архитектура
1. Перенести конфигурацию в явные профили (`development`, `staging`, `production`), зафиксировать `SECRET_KEY`, параметры БД, уровни логирования и внешние сервисы.  
2. Добавить централизованное управление миграциями и автоматическую проверку применимости Alembic перед запуском приложения.  
3. Ввести механизм health-check (проверка наличия шаблонов, доступности справочников, подключения к БД и файловым каталогам).  
4. Расширить защиту аутентификации: rate limiting на форму входа, обязательная сложность паролей, поддержка 2FA или OTP для админов.  
5. Разделить слой бизнес-логики и сервисов на интерфейсы, покрыть ключевые компоненты (калькулятор, генератор документов, импортер Excel) юнит-тестами и интеграционными тестами API.  
6. Оптимизировать работу с большими таблицами истории: пагинация на уровне SQL, lazy-loading деталей, индексы по `timestamp`, `drawing_number`, `user_id`.

## 2. Достоверность расчётов и данных
1. Формализовать и документировать константы расчёта (`calculation_constants`, `pricing.mode`), добавить UI-переключатель режимов для админов и историю изменений.  
2. Реализовать мониторинг курсов валют, ставок логистики и пошлин через API (webhook/cron), с fallback на локальные значения.  
3. Внедрить модуль аналитики мультипозиций: диаграммы маржинальности по позициям, сравнение целевой и фактической маржи, тренды логистических расходов.  
4. Настроить автоматический импорт/верификацию JSON/CSV справочников (JSON Schema + тесты) с уведомлениями при ошибках.  
5. Добавить версии и комментарии для справочников (пошлины, материалы, логистика) с возможностью отката к предыдущему снапшоту.  
6. Обогатить историю генераций: хранить развернутые параметры расчёта, источники данных, привязку к тендерам/клиентам для последующей аналитики.

## 3. Пользовательский опыт
1. Улучшить форму расчёта: динамическая проверка полей, подсказки по ошибкам, пресеты по типам клиентов, "мастер" для импорта Excel.  
2. Встроить подробный превью документов перед генерацией, подсветку отсутствующих шаблонов и быстрый переход в админку для их загрузки.  
3. Расширить личный кабинет: уведомления о просроченных КП, персональные цели, статистические карточки, геймификация для менеджеров.  
4. Добавить встроенный контактный справочник по заказчикам с поиском, тегами и привязкой к историям КП.  
5. Реализовать чат-помощника (LLM или rule-based) с доступом к инструкциям и истории расчётов для подсказок пользователям.  
6. Внедрить ночную тему и адаптивную сетку для планшетов/мобильных устройств.

## 4. Администрирование и контент
1. Создать единый центр управления шаблонами документов: предпросмотр diff, принудительное обновление кэша, автоматические тесты на наличие обязательных плейсхолдеров.  
2. Расширить Content Manager: календарь публикаций распоряжений/инструкций, ролевая модель доступа (редактор/ревьюер/публикатор).  
3. Добавить журнал действий админов (audit log) и уведомления о критичных операциях (удаление справочника, изменение тарифов).  
4. Внедрить KPI-панель в админке: топ-менеджеры, объемы генераций, средняя маржа по отделам.

## 5. Интеграции и расширения
1. Реализовать REST/GraphQL API для внешних систем: отправка заявок, получение статуса КП, импорт позиций.  
2. Добавить webhooks для событий (успешная генерация, отклонение расчёта, обновление справочника).  
3. Интегрировать CRM или чат (например, Bitrix24, Teams) для мгновенных уведомлений о новых КП и комментариях.  
4. Подключить электронную подпись/печати для автоматической подготовки документов к отправке клиенту.  
5. Реализовать экспорт/импорт настроек и справочников через UI с валидацией.

## 6. Процессы разработки и DevOps
1. Настроить CI/CD: lint + тесты (pytest, coverage), сборка фронтовых ассетов, деплой на тест/прод окружения, smoke-тесты после выката.  
2. Ввести статический анализ (mypy или pyright) и контроль форматирования pre-commit hook'ами.  
3. Добавить мониторинг и алертинг: метрики по ответам Flask, нагрузке, ошибкам, размеру БД.  
4. Настроить централизованное логирование (ELK, Loki) с поиском по ключевым событиям и кореляцией с пользователями.  
5. Организовать регулярные бэкапы БД и документов (cron + проверка восстановления).  
6. Вести технический roadmap и changelog в `docs/`, автоматизировать публикацию релизных заметок.
