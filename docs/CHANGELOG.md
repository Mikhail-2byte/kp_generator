# Обновление логики расчета маржи для множественных позиций

## Проблема

Ранее система рассчитывала маржу для каждой позиции отдельно, что не гарантировало достижение целевой итоговой маржи (например, 30%) по всем позициям в совокупности.

## Решение

Создан новый модуль `MultiPositionCalculator` с логикой расчета, которая обеспечивает точное достижение целевой маржи для всего заказа.

## Новые файлы

### `app/services/multi_position_calculator.py`
- **MultiPositionCalculator** - основной класс для расчета множественных позиций
- **calculate_multi_position_prices()** - расчет с единой итоговой маржой
- **calculate_legacy_single_position()** - обратная совместимость для одной позиции

## Измененные файлы

### `app/routes/main.py`
- Интеграция нового калькулятора
- Автоматический выбор метода расчета (одна/множественные позиции)
- Сохранение обратной совместимости

## Принцип работы

### 1. Расчет затрат для каждой позиции
```python
# Для каждой позиции рассчитываются:
- Затраты на закупку
- Логистика (пропорционально весу)
- Пошлина
- Комиссия за конвертацию
- Кредитные затраты
- Общие затраты на единицу
```

### 2. Расчет общего коэффициента цены
```python
# Общие затраты по всем позициям
total_costs = sum(position_costs)

# Целевая выручка с учетом маржи
target_revenue = total_costs / (1 - target_margin / 100)

# Коэффициент для всех позиций
price_coefficient = target_revenue / total_costs
```

### 3. Применение коэффициента
```python
# Цена каждой позиции
final_price = position_cost * price_coefficient

# Итоговая маржа точно равна целевой
actual_margin = (total_revenue - total_costs) / total_revenue * 100
```

- **Позиция 3**: 2 шт. × 1500 руб. × 8 кг = 16 кг

### Цены по позициям:

- **Позиция 2**: 3,603.26 руб./шт. (маржа: 30.00%)

## Преимущества

1. **Точность**: Итоговая маржа точно соответствует заданной
2. **Справедливость**: Все позиции получают одинаковый коэффициент маржи
3. **Прозрачность**: Понятная логика расчета
4. **Совместимость**: Старые формы с одной позицией работают без изменений
5. **Гибкость**: Поддержка любого количества позиций

## Обновление истории для работы с множественными позициями

# Обновление истории для работы с множественными позициями

## Проблема

Система истории была рассчитана только на одну позицию, что не позволяло:
- Сохранять данные о множественных позициях
- Отображать информацию о всех позициях в модальном окне
- Загружать все позиции обратно в форму

## Решение

Полностью адаптирована система истории для работы с множественными позициями с сохранением обратной совместимости.

## Изменения в базе данных

### Новая миграция: `20241220_0003_add_multi_position_fields.py`

Добавлены поля в таблицу `generation_history`:
- `positions_data` (TEXT) - JSON с данными всех позиций
- `total_general_price` (FLOAT) - Общая стоимость всех позиций
- `positions_count` (INTEGER) - Количество позиций (по умолчанию 1)

## Обновленные файлы

### 1. `app/models.py`
- **GenerationHistoryRecord**: Добавлены поля для множественных позиций
- Сохранена обратная совместимость со старыми записями

### 2. `app/database.py`
- **save_generation_history()**: 
  - Извлекает все позиции из формы
  - Сохраняет их в JSON формате
  - Рассчитывает общий вес всех позиций
  - Сохраняет количество позиций и общую стоимость

- **load_generation_data()**:
  - Загружает данные множественных позиций из JSON
  - Преобразует их обратно в формат формы с суффиксами
  - Поддерживает старые записи (одна позиция)

- **get_generation_details()**:
  - Возвращает данные всех позиций для модального окна
  - Добавляет информацию о количестве позиций
  - Включает общую стоимость

- **get_generation_history()**:
  - Добавляет поле `positions_count` в список истории

### 3. `app/routes/main.py`
- Обновлен вызов `save_history()` с передачей `total_general_price`

### 4. `templates/history.html`
- **Таблица истории**:
  - Добавлена колонка "Позиций" с бейджами
  - Отображение количества дополнительных позиций в названии товара
  - Цветовая индикация множественных позиций

- **Модальное окно**:
  - Отображение всех позиций в отдельной секции
  - Детальная информация по каждой позиции
  - Общая стоимость заказа
  - Адаптивный дизайн для множественных позиций

### 5. `static/css/style.css`
- **Стили для позиций**:
  - `.positions-list` - контейнер для списка позиций
  - `.position-item` - карточка отдельной позиции
  - `.position-header` - заголовок с номером и ценой
  - `.position-details` - детали позиции в сетке
  - `.badge-primary/secondary` - индикаторы количества позиций

## Принцип работы

### Сохранение данных
1. **Извлечение позиций**: `extract_positions_from_form()` находит все позиции
2. **JSON сериализация**: Позиции сохраняются в поле `positions_data`
3. **Метаданные**: Сохраняются `positions_count` и `total_general_price`
4. **Совместимость**: Основные поля заполняются данными первой позиции

### Загрузка данных
1. **Проверка типа**: Определяется, есть ли данные множественных позиций
2. **JSON десериализация**: Позиции загружаются из `positions_data`
3. **Преобразование формы**: Позиции преобразуются в формат с суффиксами
4. **Fallback**: При ошибке используются старые поля

### Отображение в истории
1. **Список**: Показывается количество позиций с цветовой индикацией
2. **Модальное окно**: Детальное отображение всех позиций
3. **Финансы**: Общая стоимость и цена за единицу
