# Обновление развёрнутой версии без потери данных

Инструкция для обновления KP Generator на другом ПК (или том же), когда новая версия получена копированием файлов, а не через git. Цель — обновить код и конфиг, **сохранив базу данных** (история генераций, пользователи, пароли).

## Почему «просто не трогать БД» — правильный подход

- Приложение при старте вызывает `init_db()` и выполняет **Alembic `upgrade head`**.
- Текущая ревизия схемы хранится **в самой БД** (таблица `alembic_version`).
- При запуске новой версии Alembic видит эту ревизию и применяет **только недостающие** миграции (новые файлы из папки `migrations/versions/`).
- Старые миграции повторно не выполняются, данные не затираются. Ошибки версий не возникнут, если вы не меняете сервер и строку подключения к **Microsoft SQL Server** в `.env`.

Итого: можно смело заменить все файлы проекта на новую версию, **сохранив `.env`** (в нём задан `DATABASE_URL` к вашей БД). После первого запуска схема будет доведена до актуальной автоматически на сервере MS SQL.

## Что сохранить на целевом ПК (где уже работает стабильная версия)

Перед обновлением обязательно сохраните:

1. **Файл `.env`**  
   - В нём заданы `DATABASE_URL` (подключение к Microsoft SQL Server), `SECRET_KEY`, Redis и т.д. Не перезаписывайте его при копировании новой версии или вручную добавьте в него новые переменные при необходимости.

2. **Резервная копия БД на сервере MS SQL** (рекомендуется)  
   - Делается средствами SQL Server (backup базы). Данные приложения хранятся на сервере, не в файле проекта.

3. **Папка `logs/`** (по желанию)  
   - Можно не переносить при обновлении, но если нужна старая история логов — скопируйте её отдельно перед заменой файлов.

## Пошаговое обновление (без git на целевом ПК)

Выполняйте на **целевом ПК**, где уже запущена стабильная версия.

### 1. Остановить приложение

Остановите сервер (Flask/Waitress и т.д.).

### 2. Сделать резервную копию

- Рекомендуется сделать backup базы на сервере Microsoft SQL Server (средствами SQL Server).
- Скопируйте в безопасное место `.env` и при необходимости папку `logs/`.

### 3. Заменить файлы проекта на новую версию

- Возьмите архив/папку с **новой** версией проекта.
- Скопируйте из неё **все** файлы и папки в каталог установки на целевом ПК (перезапись).
- **Исключите из копирования** (не перезаписывайте): `.env` (если на целевом ПК он уже настроен).

То есть: код, `config/`, `migrations/`, `templates/`, `static/`, `requirements.txt`, `app.py` и т.д. — из новой версии; `.env` — с целевого ПК (в нём ваш `DATABASE_URL` к MS SQL).

### 4. Виртуальное окружение и зависимости (рекомендуется)

В каталоге проекта на целевом ПК:

```bash
# Активировать venv (пример для Windows)
.\venv\Scripts\Activate.ps1

# Обновить зависимости из новой версии
pip install -r requirements.txt
```

Так вы подтянете новые/обновлённые пакеты, если в новой версии изменился `requirements.txt`.

### 5. Запустить приложение

Запустите приложение как обычно (например, `python app.py` или через Waitress). При первом старте:

- выполнится `init_db()` → `alembic upgrade head`;
- применятся только **новые** миграции (которых не было в старой версии);
- история, пользователи и пароли останутся в той же БД.

### 6. Проверить работу

- Вход под существующими учётными записями.
- История генераций на месте.
- При необходимости — проверить новые функции из обновления.

## Подключение к Microsoft SQL Server

Приложение работает только с Microsoft SQL Server. В `.env` задаётся `DATABASE_URL` в формате `mssql+pyodbc://...`. При обновлении не меняйте эту строку; заменяйте только файлы проекта. При запуске новой версии миграции применятся к существующей БД — только недостающие шаги.

## Если что-то пошло не так

- Остановите приложение.
- Верните на место резервную копию `kp_generator.db` (и при необходимости старый `.env`).
- Можно временно вернуть и старую версию кода из своей копии и разобраться (логи в `logs/`).
- При ошибках миграций смотрите `logs/kp_generator.log` и `logs/kp_generator_errors.log` — там будет трейсбек и ревизия Alembic.

## Краткий чеклист

- [ ] Остановить приложение.
- [ ] Сделать копию `.env` и при необходимости backup БД на SQL Server, `logs/`.
- [ ] Скопировать все файлы новой версии, **не перезаписывая** `.env` (если он уже настроен).
- [ ] Обновить зависимости: `pip install -r requirements.txt`.
- [ ] Запустить приложение и убедиться, что логины и история на месте.

После этого проект будет на новой версии с сохранёнными данными.
