========================================
Инструкция по работе с системой KP Generator
========================================

Общее описание
---------------
KP Generator — это веб-приложение на базе Flask для подготовки коммерческих предложений. Система позволяет рассчитать стоимость изделий, сформировать комплект документов (Excel + Word), вести историю генераций и управлять справочными данными через административный интерфейс.

Технические требования
----------------------
1. Python 3.12 (или совместимый) установлен в системе.
2. Утилита `pip` доступна для установки зависимостей.
3. Git используется для управления версией проекта (рекомендуется).
4. Операционная система: Windows 10/11, macOS или Linux.

Подготовка окружения
--------------------
1. Клонируйте репозиторий или скопируйте файлы проекта на локальную машину.
2. Создайте виртуальное окружение Python:
   ```bash
   python -m venv venv
   ```
3. Активируйте окружение:
   - Windows PowerShell: `venv\Scripts\Activate.ps1`
   - Windows CMD: `venv\Scripts\activate.bat`
   - Unix/macOS: `source venv/bin/activate`
4. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   pip install -r requirements-dev.txt
   ```

Конфигурация
------------
1. Скопируйте файл `.env.example` в `.env` и при необходимости заполните значения (секретный ключ, строка подключения к БД и т.д.).
2. При необходимости отредактируйте `config/settings.json` — там задаются константы расчёта, пути к шаблонам и ограничения интерфейса.

Инициализация базы данных
-------------------------
1. Создайте физический файл БД, выполнив миграции Alembic:
   ```bash
   alembic upgrade head
   ```
2. По умолчанию используется SQLite (`kp_generator.db` в корне проекта). Для внешней БД измените переменную `DATABASE_URL`.

Запуск приложения
-----------------
1. Убедитесь, что виртуальное окружение активировано и зависимости установлены.
2. Режим разработки (локально):
   ```bash
   python app.py
   ```
   Можно также использовать `flask --app app run`.
3. Production-запуск: установите переменную `USE_WAITRESS=1` в `.env` и выполните:
   ```bash
   waitress-serve --call "app:create_app"
   ```
4. Приложение будет доступно по адресу http://127.0.0.1:5000/ (или по хосту/порту из переменных окружения).

Основной функционал
-------------------
1. **Генерация КП**: заполните форму на главной странице. После успешной валидации система рассчитает цену, сохранит результат и предложит архив с документами.
2. **История**: раздел «История генераций КП» отображает последние расчёты с возможностью подробного просмотра и повторной загрузки данных в форму.
3. **Обратная связь**: страница «Обратная связь» сохраняет отзывы пользователей в файл `data/feedback_entries.jsonl`.
4. **Справочники**: разделы «Аналоги GB», «Ставки пошлин», «Логистика» используют данные из папки `config` и доступны как справочная информация.

Работа с пользователями
-----------------------
1. Регистрация и вход доступны на странице профиля `/profile`.
2. После входа пользователь видит статистику последних генераций.
3. Доступен функционал обновления профиля и удаления учётной записи с отвязкой истории.

Административный интерфейс
---------------------------
1. Раздел `/admin` доступен только пользователям с ролью `admin`.
2. Через интерфейс можно добавлять, редактировать и удалять:
   - Ставки пошлин;
   - Аналоги материалов по стандарту GB;
   - Города с тарифами логистики.
3. После каждого изменения данные сохраняются в JSON-файлы в каталоге `config` и обновляются в памяти без перезапуска сервера.

Работа с шаблонами документов
-----------------------------
1. Шаблоны Excel и Word располагаются в каталоге `templates_docs`.
2. Файл `templates_docs/template.xlsx` используется для формирования табличной части расчёта.
3. Файл `templates_docs/template.docx` содержит текстовую часть коммерческого предложения.
4. При генерации создаётся ZIP-архив с обоими документами и понятным именем (организация + дата/время).

Тестирование и контроль качества
--------------------------------
1. Юнит- и интеграционные тесты расположены в каталоге `tests`. Запуск:
   ```bash
   pytest
   ```
2. Для проверки стиля и статического анализа используются инструменты Black и Ruff:
   ```bash
   black --check .
   ruff check .
   ```
3. GitHub Actions (`.github/workflows/ci.yml`) автоматически выполняет lint и тесты при push/PR.

Полезные команды
---------------
- Перегенерация справочников в памяти без перезапуска: перезапустить приложение или вызвать функции `datasets.refresh_*` в интерактивной консоли.
- Создание администратора: используйте скрипт `scripts/manage_users.py set-role <username> admin` или вручную обновите столбец `role` в таблице `users`.
- Проверка наличия шаблонов: функция `check_templates_exist` сообщает о проблемах при генерации.

Резервное копирование и обновление
----------------------------------
1. Регулярно делайте резервные копии каталога `config` (справочные данные) и `templates_docs` (шаблоны документов).
2. Перед обновлением зависимостей просматривайте `requirements.txt` и `requirements-dev.txt`.
3. После применения миграций обновляйте документацию и информируйте пользователей об изменениях схемы данных.

Безопасность
------------
1. Секретные ключи, строки подключения и пароли храните в переменных окружения или `.env`.
2. Не храните реальные данные клиентов в репозитории — используйте локальную БД.
3. Для публикации приложения настройте HTTPS, ротацию логов и ограничение прав пользователей.

Обратная связь и сопровождение
------------------------------
1. Записи об ошибках можно найти в `logs/kp_generator.log` и `logs/kp_generator_errors.log`.
2. Для предложений по улучшению используйте встроенную форму обратной связи или отправляйте issue в репозиторий.

Следующие шаги
--------------
- Настройте автоматическую очистку истории генераций (cron или celery) при большом объёме данных.
- Добавьте двухфакторную аутентификацию для администраторов.
- Расширьте тестовое покрытие, включая формы и административные сценарии.
